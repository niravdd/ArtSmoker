## 📌 0. 概要

Amazon Bedrockの画像・動画生成モデルのためのシンプルでアーティストフレンドリーなインターフェース。ArtSmokerは、API、CLI、プロンプトエンジニアリングを学ぶことなく、クリエイティブチームがBedrockを効率的に使えるようにします。

### 📝 課題

クリエイティブチームやゲームスタジオはAIによるアセット生成を活用したいと考えていますが、実際には多くの障壁があります：

- **シンプルなインターフェースがない** — アーティストが画像を生成するためにBedrockコンソールにログインしたりAPIコールを書いたりする必要があってはなりません
- **プロンプトエンジニアリングは難しい** — 適切なネガティブプロンプト、スタイル指示、モデル固有のフォーマットを含む効果的なプロンプトの作成には、ほとんどのアーティストが持っていない専門知識が必要です
- **チームは独自のモデルを構築/トレーニングしない** — Bedrockで既に利用可能な多くのモデルに、実際に使えるものを通じてアクセスする必要があります
- **画像編集がアクセスしにくい** — インペインティング、アウトペインティング、検索＆置換、スタイル転送はすべてAPI知識が必要です

### 📝 ソリューション

ArtSmokerは、Amazon Bedrockをクリーンなクリエイティブインターフェースでラップするセルフホスト型Webアプリケーションです。ゲームアセット制作に特化して構築されており、広告、Eコマース、出版、デジタルメディアなど、AI生成のビジュアルコンテンツが価値を持つ他のクリエイティブ産業にも適用できます。

- **アーティストは自然言語で必要なものを説明するだけ** — ArtSmokerがプロンプトの構成、ネガティブプロンプトの抽出、モデル固有のフォーマット、スタイルの適用を裏側で処理します
- **スタイル認識生成** — ゲームの既存アートをアップロードすると、ArtSmokerのビジョンモデルがビジュアルアイデンティティを学習します。生成されるすべてのアセットがゲームの見た目と雰囲気に合致します
- **すべてのBedrockモデル、すべてのリージョン** — 完全に設定可能。テキストから画像へのモデル、動画モデル、リージョンを選択できます。システムはBedrock APIを通じて利用可能なモデルを動的に検出します
- **セルフデプロイ、セルフ課金** — 自分のインフラで実行し、自分のAWSアカウントを使用。共有エンドポイントなし、サードパーティのデータアクセスなし、外部サービスからの予期しない請求なし

Amazon Bedrock上に構築：Claude Sonnet/Opus（プロンプトエンジニアリング＆チャット）、Nova Canvas、Titan Image、Stable Diffusion 3.5 Large、Stable Image Ultra、Stability AI（画像編集）、Nova Reel、Luma AI Ray（動画生成）、さらにChat Studio用に16プロバイダーから80以上のLLM。

## 📌 1. 機能概要

ArtSmokerは2つのモードで動作します — **スタンドアロン**（アートスタイルやテーマの設定不要、説明して生成するだけ）と**スタイルガイド**（既存のアートをアップロードして、すべての生成がビジュアルアイデンティティに合致）。両モードとも同じスタジオと生成パイプラインを使用します。

### 📝 スタンドアロンモード（クイックスタート）

スタイルやテーマの設定不要 — 2D Image Studio、Video Studio、またはType Studioを開いてすぐに制作を開始できます。

1. **必要なものを説明** — 「hospital building」や「fire mage character」のようなプロンプトを入力するか、音声入力を使用。AIが適切な構成指示、ネガティブプロンプト、モデル固有のフォーマットでプロンプトを自動的に強化します。
2. **モデルと設定を選択** — Amazon Bedrockで利用可能なすべてのテキストから画像へのモデルから選択し、寸法、品質ティア、リージョンを選択。または「All Available Models」を使用して、有効なすべてのモデルで同時に生成し、横並び比較ができます。
3. **複数のオプションを取得** — システムは最大5つの異なるクリエイティブコンセプトを生成し、それぞれ最大5つのシードバリエーション（合計25画像）を持ちます。好みのものを選んでください。
4. **編集と改良** — Asset Viewerで直接インペインティング、アウトペインティング、消去、検索＆置換、リカラーを使用。各編集は新しいバージョンを作成 — オリジナルは常に保持されます。
5. **ゲーム対応ファイルをダウンロード** — 透明背景のPNG + SVG、説明的な名前付き（例：`hospital-building_opt2_var3.png`）。動画はMP4でエクスポート。

### 📝 スタイルガイドモード（アートスタイルとテーマに合わせる）

生成されるすべてのアセットを既存のアートスタイルに合わせたいチーム向け — リファレンス画像をアップロードして、AIにビジュアルアイデンティティを学習させます。

1. **ゲームのアートをアップロード** — ローカルディレクトリ（再帰スキャン、重複回避のためシンボリックリンク）またはS3バケット（ページネーション付き再帰リスト）からリファレンス画像をインポート。**スマート重複排除**が自動実行 — 回転バリアント（barrel_N/E/S/W.pngからbarrel_S.pngのみ保持）とアニメーションフレーム（Idle0-Idle8からIdleのみ保持）を除去。例えば、747ファイルのアイソメトリックアセットパックが約99のユニークオブジェクトに重複排除されます。対応フォーマット：.png、.jpg、.jpeg、.gif、.bmp、.webp、.tiff、.tif、.tga、.ico、.svg、さらに3Dモデル（.glb、.gltf）からの自動テクスチャ抽出。
2. **AIがスタイルを学習** — 2フェーズのコヒージョン認識分析：まず、コレクションが統一されているか、構造的に一貫しているか、多様かを判定するクイックチェック。次に、完全なリファレンスセットの詳細分析がメタデータリッチなスタイルプロファイル — カラーパレット、線の太さ、照明パターン、構図ルール、制作規約を生成。生成ヒントを提供すると、AIはそれを「アーティストのガイダンス」として受け取り、分析が見た目だけでなく意図も理解します。
3. **スタイル適用で生成** — Image Studioでスタイルを選択すると、すべてのプロンプトがスタイルのビジュアル指示で自動的に強化されます。「hospital building」のようなプロンプトが、ゲームのカラーパレット、パースペクティブ規約、レンダリングスタイルを含む詳細な生成指示になります。
4. **スタンドアロンモードのすべてが適用** — 複数オプション、モデル比較、編集、バージョニング、ゲーム対応ダウンロードはすべて同じように機能し、アートスタイルによってガイドされます。

> [!NOTE]
> 生成されるすべてのコンテンツはAIモデルによって作成され、提供するプロンプトとリファレンスに依存します。本番環境で生成アセットを使用する前に、コンテンツ品質、知的財産、適用されるサービス条件に関する[免責事項](#disclaimer)をご確認ください。

### 📝 1.3 2段階生成

各プロンプトに対して、AIは**オプション** — 根本的に異なるデザイン解釈（例：「warrior」の場合：ヴァイキングバーサーカー、日本のサムライ、部族の戦士、サイバーソルジャー、ギリシャのホプリタイ）を作成します。各オプションに対して、画像モデルは**バリエーション** — 微妙な視覚的違いを与える異なるランダムシードを生成します。これによりアーティストは幅広いクリエイティブパレットから選択できます。

### 📝 1.4 All Available Models

モデルドロップダウンから**「All Available Models」**を選択すると、有効なすべての画像モデルで同時にプロンプトを生成します — モデルごとに1画像。Nova Canvas、Titan Image、SD 3.5 Large、Stable Image Ultraがそれぞれ同じプロンプトをどう解釈するかを直接比較できます。各モデルは独立して実行されます：厳格なモデルがプロンプトをブロックしても、受け入れたモデルからの結果は得られ、各オプションカードに明確なステータスラベル（成功、モデレーションによりブロック、または失敗）が表示されます。

オプションの**「Model-optimized prompts」**トグルは、同じプロンプトをすべてに送信する代わりに、各モデルの強みに合わせてプロンプトを調整します — 直接比較ではなく、各モデルから最良の出力を得たい場合に便利です。

### 📝 1.5 Video Studio

テキストプロンプトからAI動画やアニメーションを生成。**Amazon Nova Reel**（v1.0、v1.1）と**Luma AI Ray**（v2.0）に対応。

| 機能 | Nova Reel | Luma Ray v2 |
|------|-----------|-------------|
| **最大長** | 120秒（2分） | 9秒 |
| **解像度** | 1280x720 | 720p / 540p |
| **アスペクト比** | 16:9のみ | 7オプション（1:1、16:9、9:16等） |
| **画像から動画** | はい（開始フレーム） | はい（開始＋終了フレーム） |
| **ループ動画** | なし | はい |
| **マルチショット制御** | はい（自動＋手動） | なし |
| **価格** | ～$0.08/秒 | ～$1.50/秒 |

**仕組み：**
1. 動画モデルを選択し、長さ、アスペクト比、リージョンを設定
2. プロンプトを入力 — AIが映画的語彙、カメラワーク、時間的一貫性のキューで強化
3. Generateをクリック — ジョブは`StartAsyncInvoke`を通じて非同期実行、出力は設定されたS3バケットへ
4. 5秒ごとにステータスをポーリング — 完了時、サムネイルが抽出され（ffmpeg経由）、MP4がローカルにダウンロード（またはS3からストリーミング）
5. 動画はVideo Studioの「Recent Videos」セクションと統合ギャラリーの両方に表示

**S3バケットが必要**：動画生成はS3に出力します。UIのVideo Settingsで設定（既存バケットの参照または新規作成）するか、CLIで作成できます：

```bash
# 動画ストレージ用のS3バケットを作成（REGIONとYOUR_ORGを置換）
aws s3api create-bucket --bucket artsmoker-video-YOUR_ORG --region us-east-1

# us-east-1以外のリージョンの場合、LocationConstraintを追加：
aws s3api create-bucket --bucket artsmoker-video-YOUR_ORG --region us-west-2 \
  --create-bucket-configuration LocationConstraint=us-west-2
```

ストレージモード：ローカルにダウンロード（デフォルト）またはS3からオンデマンドストリーミング。

**動画プロンプト強化**：LLMがカメラワーク（パン、ズーム、ドリー、トラッキング）、照明の詳細、時間的キューを追加。動画モデルはネガティブプロンプトをサポートしないため、回避コンセプトは自然にポジティブプロンプトに織り込まれます。

### 📝 1.6 Chat Studio

フル機能のLLMチャットインターフェース — セルフホスト型の対話AI、サードパーティのデータアクセスなしで自分のAWSアカウントで動作。

**16プロバイダーから80以上のモデル** — Claude（Sonnet、Opus、Haiku）、Amazon Nova、Meta Llama、Mistral、Cohere、Qwen、DeepSeek、Google Gemma、NVIDIA Nemotronなど。さらにアカウント内のカスタム/インポートモデル。すべてSync from AWSで自動検出。

**コア機能：**
- **ストリーミングレスポンス** — Bedrock ConverseStreamによるリアルタイムトークン単位レンダリング
- **Markdownレンダリング** — 見出し、太字/斜体、リスト、テーブル、引用、水平線
- **コードブロック** — 言語バッジ＋コピーボタン付きシンタックスハイライト（highlight.js）
- **メッセージごとのメトリクス** — 入力/出力トークン、レイテンシ、推定コスト、使用モデル
- **コンテキストウィンドウバー** — 使用/最大トークン数付きビジュアル充填インジケーター（緑/黄/赤）
- **リージョン切り替え** — 各モデルが利用可能なすべてのリージョンを表示、最も近いまたは最も安いものを選択

**セッション管理：**
- 自動保存付き複数同時セッション
- サイドバーでのインライン名前変更、複製、削除、検索/フィルター
- 会話をMarkdownとしてエクスポート
- セッション合計：トークン数、推定コスト、メッセージ数

**高度な機能：**
- **システムプロンプトテンプレート** — General Assistant、Coding Expert、Creative Writer、Game Designer、Data Analyst、Technical Writer
- **ビジョン/マルチモーダル** — ビジョン対応モデル用のドラッグ＆ドロップ、ファイルピッカー、Ctrl+V画像貼り付け
- **コンテキスト圧縮** — AIが古いメッセージを要約してコンテキストウィンドウスペースを解放
- **再生成** — 同じプロンプトでAIレスポンスを再実行
- **編集＆再送** — 任意のユーザーメッセージを修正してそのポイントからリプレイ
- **フォーク** — 任意のメッセージから会話を新しいセッションに分岐

**料金の透明性：** モデルピッカーは1Kトークンあたりのコストを表示、料金情報バーは10Kおよび100Kトークン会話の推定コストを表示。

### 📝 1.7 アセットタイプ認識

選択された**アセットタイプ**は、AIがプロンプトをどう解釈するかを根本的に変えます — 画像モデルだけでなく、パイプラインのすべての段階で。「hospital」と入力して異なるアセットタイプを選択すると、まったく異なる出力が得られます：

| タイプ | 構図 | フレーミング | 技術的アプローチ |
|--------|------|-------------|----------------|
| **Game Asset** | 透明背景に単一の分離されたオブジェクト。シーン、テキスト、UIなし。 | 正面またはアイソメトリック、オブジェクトがフレームの70-80%を占める。 | bg除去用のクリーンなシャープエッジ、一貫した左上照明、地面の影なし。様々なスケールで他のゲームアセットと合成するよう設計。 |
| **Character** | クリーンな背景に分離されたフルボディまたは3/4ボディのフィギュア。キャラクター1体のみ。 | キャラクターが垂直の60-75%を占め、頭からつま先、やや中心からずれて。 | 強い読みやすいシルエット（シルエットだけで識別可能）、パーソナリティを伝える表現力のあるポーズ、明確な顔の特徴と衣装の詳細。 |
| **Icon** | 単一の大胆で認識しやすいシンボル、余裕のあるパディングで中央配置。最大限のシンプルさ。 | 正面またはわずかな3/4傾き、エッジに余裕。 | 64x64ピクセルで明確に読めること。高コントラスト、最大3-5色、大胆な形状、細い線や細かいディテールなし。 |
| **Marketing Banner** | ドラマチックな構図のフルシーンイラスト。片側にクリーンなテキストセーフゾーン — レンダリングされたテキストやタイポグラフィなし。 | ワイドなシネマティック感、シーンを見せるためにカメラを引く。 | 豊かな彩度の色、ドラマチックな照明（リムライト、ボリューメトリックレイ）、被写界深度。AIはテキストをレンダリングしないよう明示的に指示され、テキストセーフゾーンはデザインツール（Figma、Canva等）でのポストプロダクションオーバーレイ用にクリーンに保たれます。 |
| **Environment** | 前景/中景/背景の深度レイヤーとリーディングラインを持つフルランドスケープ。 | ワイドなエスタブリッシングショット、地平線は上部または下部の3分の1。 | 大気遠近法（遠いオブジェクトはより明るく/ぼんやり）、ディテールによる環境ストーリーテリング、ムード設定照明。 |

これはすべての段階で重要です：

- **「Preview Enhanced Prompt」ボタン** — Composeをクリックすると、AIがアセットタイプを使って簡潔な説明を詳細な生成プロンプトに再構成し、あなたの言葉をスタイルガイドラインとアセットタイプ指示と組み合わせます。あなたの明示的な意図は常にスタイルデフォルトよりも優先されます。生成前に構成されたバージョンを確認できます。
- **コンセプト生成** — 複数のオプションを生成する際、AIはアセットタイプの構造ルールをすべて尊重するN個の異なるデザイン解釈を作成します。Characterオプションは常に読みやすいシルエットを持ち、Marketing Bannerオプションは常にレンダリングされたテキストのないテキストセーフゾーンを持ちます。
- **結果** — 同じプロンプトでも異なるアセットタイプの2つの画像はまったく異なって見えます。Game Assetの「warrior」は中央配置の単一キャラクタースプライト。Marketing Bannerの「warrior」はヘッドラインオーバーレイ用のクリーンゾーン付きのエピックバトルシーン。

## 📌 2. 前提条件

### 📝 2.1 AWS認証情報

ArtSmokerは[boto3の標準認証情報解決](https://boto3.amazonaws.com/v1/documentation/api/latest/guide/credentials.html#configuring-credentials)を使用するため、以下のいずれかの方法が機能します：

| 方法 | 最適な用途 | 方法 |
|------|-----------|------|
| **環境変数** | CI/CD、コンテナ | `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` |
| **共有認証情報ファイル** | ローカル開発 | `~/.aws/credentials`（`aws configure`経由） |
| **名前付きプロファイル** | 複数アカウント | `ARTSMOKER_AWS_PROFILE=myprofile`または`AWS_PROFILE`を設定 |
| **AWS SSO** | エンタープライズSSO | `aws configure sso` |
| **IAMインスタンスプロファイル** | EC2、ECS、App Runner | インスタンスにIAMロールをアタッチ — マシン上に認証情報不要 |
| **ECSタスクロール** | ECS/Fargateコンテナ | 必要なパーミッションのタスク実行ロールを割り当て |

認証情報が機能しているかのクイックチェック：

```bash
aws sts get-caller-identity
```

> [!NOTE]
> EC2やその他のAWSコンピューティングサービスでは、明示的な認証情報を設定する必要はありません。必要なパーミッションを持つ[IAMインスタンスプロファイル](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-ec2_instance-profiles.html)をアタッチすれば、boto3がインスタンスメタデータサービス経由で自動的に取得します。

詳細なIAMパーミッション、インストール手順、設定オプション、料金情報については、[英語版README](README.md)のセクション2.1.1〜2.4、セクション3〜4、セクション11〜12を参照してください。

## 📌 8. セキュリティモデル

ArtSmokerは**ローカル/信頼されたネットワーク開発ツール**として設計されています — 開発者自身のマシンまたはプライベートEC2インスタンスで動作します。

- **認証なし** — すべてのAPIエンドポイントがオープン。ローカル開発とプライベートチームデプロイに適切。
- **ファイルシステムブラウザ** — `GET /api/browse/local`エンドポイントはサーバープロセスがアクセスできる任意のディレクトリの閲覧を許可。リファレンスアートのインポート用として意図的。
- **S3アクセス** — S3の閲覧とインポートはサーバーのAWS認証情報を使用。

> [!WARNING]
> 認証とパス制限を追加せずに、信頼されていないネットワークにArtSmokerを公開しないでください。本番環境の強化ガイダンスについては[SPEC.mdのデプロイメントロードマップ](SPEC.md#14-deployment--scaling-roadmap)を参照してください。
